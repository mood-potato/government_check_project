# Dev Guide — 개발 단계 수직 슬라이싱

## 태스크 수신 시 즉시 확인

태스크를 받으면 먼저 크기를 판단한다:

| 크기 | 파일 수 | 처리 |
|------|--------|------|
| S    | 1~2개  | 즉시 진행 |
| M    | 3~5개  | 범위 확인 후 진행 |
| L    | 6개+   | **거절 → 분해 안내** |

**L 크기 거절 응답:**
```
이 태스크는 한 번에 진행하기에 너무 큽니다.
다음과 같이 분해를 제안합니다:
1. [서브 태스크 1] — [파일 목록]
2. [서브 태스크 2] — [파일 목록]
3. [서브 태스크 3] — [파일 목록]
어떤 것부터 시작할까요?
```

---

## 실행 순서

### Step 1: 가정 드러내기

구현 전에 반드시 출력한다:

```
구현을 시작하기 전에 가정하고 있는 것들을 나열합니다:
- [API 응답 shape / 상태 관리 방식 / 데이터 구조 등]
확인해주시면 시작하겠습니다.
```

### Step 2: 파일 범위 명시

```
이번 태스크에서 수정할 파일:
- [파일 경로]: [변경 내용 요약]
- [파일 경로]: [변경 내용 요약]

범위 밖에서 발견하는 문제는 수정하지 않고 마지막에 알려드립니다.
```

파일 범위를 명시하지 않은 태스크는 범위 제안 → 사용자 확인 후 시작한다.

### Step 3: 구현

- 범위 내 파일만 수정
- 범위 밖 문제 발견 시 → 메모만 하고 계속 진행
- 불확실한 부분 발견 시 → **멈추고 확인 요청**

**멈추는 기준:**
- 두 가지 구현 방향이 있고 어느 것이 맞는지 알 수 없을 때
- 기존 코드의 의도가 불명확해서 수정 방향을 판단할 수 없을 때
- 요구사항과 기존 코드가 충돌할 때

### Step 4: 완료 보고

"완료됐습니다"로 끝내지 않는다. 반드시 증거를 포함한다:

```markdown
## 구현 완료

### 변경된 파일
- [파일]: [변경 내용]

### 확인한 케이스
- [케이스]: [어떻게 확인했는지]
- [케이스]: [어떻게 확인했는지]

## 범위 밖 발견 사항
(이번 태스크에서 수정하지 않음 — 별도 태스크로 처리 필요)
- [파일/기능]: [발견한 문제]
```

## 반복 패턴 경고

같은 보일러플레이트를 3회 이상 작성하게 되면 멈추고 제안한다:
"이 패턴이 반복되고 있습니다. 공통 유틸/헬퍼로 추출하는 것이 좋을 것 같습니다. 별도 태스크로 진행할까요?"

직접 추출하지 않는다. 사용자의 결정을 받는다.
