# Flow Create — 서비스 플로우 초안 생성

## 목적

flow-review가 검토할 수 있는 플로우 초안을 만드는 것이다. 완벽한 플로우가 목표가 아니다 — 모든 케이스를 커버하려 하지 않는다. 그것은 flow-review의 역할이다.

---

## 실행 순서

### Step 1: 가정 드러내기

생성 전에 반드시 가정 목록을 먼저 출력한다.

```
이 플로우를 작성하면서 가정하고 있는 것들을 먼저 나열합니다:
- [가정 1]
- [가정 2]
...
확인해주시면 작성을 시작하겠습니다.
```

사용자가 확인하면 Step 2로 진행한다.

### Step 2: 플로우 구성

아래 순서로 작성한다:

1. **Happy Path 먼저** — 정상 흐름의 각 단계를 순서대로 나열
2. **주요 분기 추가** — 로그인 여부, 권한 수준 등 흐름을 나누는 조건
3. **외부 의존성 명시** — 각 단계에서 호출하는 API, DB, 외부 서비스 표시

### Step 3: 출력

```markdown
## 서비스 플로우: [기능명]

### 전제조건
- [사용자 상태, 권한, 환경 전제]

### Happy Path
1. [단계 1]
2. [단계 2]
3. ...

### 주요 분기
- [조건 A]: [분기 흐름 설명]
- [조건 B]: [분기 흐름 설명]

### 외부 의존성
- [API/DB/서비스]: [어느 단계에서 어떻게 사용]
```

---

## 핵심 원칙

**초안이다.** 누락 케이스를 일부러 남겨둔다는 게 아니라, 발견되지 않은 케이스가 있어도 괜찮다. flow-review가 그 역할을 한다.

**멈추는 기준:** 기능 설명이 너무 추상적이어서 단계를 나눌 수 없을 때 → 구체적인 예시나 사용자 행동을 먼저 묻는다.
