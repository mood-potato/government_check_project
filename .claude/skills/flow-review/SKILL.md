# Flow Review — 서비스 기획 단계 플로우 검토

## 실행 순서

### Step 1: 가정 드러내기
플로우를 분석하기 **전에** 반드시 가정 목록을 먼저 출력한다.

```
지금 이 플로우를 보면서 가정하고 있는 것들을 먼저 나열합니다:
- [가정 1]
- [가정 2]
...
확인해주시면 검토를 시작하겠습니다.
```

사용자가 확인하면 Step 2로 진행한다. 확인 없이 바로 검토하지 않는다.

### Step 2: 체계적 검토

4가지 영역을 순서대로 검토한다:

**① AI 기능 실패 분기**
- 응답 타임아웃 처리
- 신뢰도/확신도 낮은 경우
- 모델 서버 오류
- 예상 외 형식의 응답

**② 사용자 권한 오류**
- 미인증 상태에서의 접근
- 권한 부족 (역할 기반)
- 세션 만료 중 작업
- 동시 접근 충돌

**③ 빈 상태 (Empty States)**
- 데이터가 아직 없는 상태
- 필터 결과 없음
- 로딩 중 상태
- 에러 후 복구 상태

**④ 분기 누락**
- 조건문에서 else 없는 경우
- 비동기 처리 중 사용자 이탈
- 네트워크 단절 시 처리

### Step 3: 우선순위 분류

발견한 케이스를 다음으로 분류한다:

| 등급 | 기준 |
|------|------|
| 블로킹 | 서비스 불가, 데이터 손실, 보안 취약 |
| 주요 | UX 훼손, 기능 오작동, 혼란 야기 |
| 선택 | 개선 권고, 엣지 케이스 보완 |

### Step 4: 출력

```markdown
## 발견된 누락 케이스

### 블로킹
- [플로우 위치]: [문제 설명]

### 주요
- [플로우 위치]: [문제 설명]

### 선택
- [플로우 위치]: [문제 설명]

## 확인 필요 사항
- [불명확한 부분에 대한 질문]
```

## 핵심 원칙

**창작하지 않는다.** 사용자가 의도하지 않은 새 기능을 제안하거나, 플로우를 통째로 재설계하지 않는다. 오직 빠진 케이스만 발굴한다.

**멈추는 기준:** 플로우가 너무 추상적이어서 어디서 실패가 발생하는지 판단 불가능할 때 → 추측하지 말고 명시적으로 멈춘다.
