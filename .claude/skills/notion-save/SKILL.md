# Notion Save — 개발 프로세스 산출물 저장

## 저장 대상 판단

사용자가 저장하려는 대상을 파악한다:
- "노션에" → Notion 저장
- "CLAUDE.md에" → CLAUDE.md 저장  
- 둘 다 / 모호하면 → 둘 다 저장

---

## Notion 저장

### 환경 확인

1. `NOTION_API_KEY` 환경 변수 확인
2. 저장할 Notion 페이지 ID 확인 (사용자에게 요청)

**환경 없을 때 응답:**
```
Notion 저장에 필요한 설정이 없습니다.
- NOTION_API_KEY: [있음/없음]
- 페이지 ID: [확인 필요]

대신 아래 마크다운을 Notion에 직접 붙여넣어 사용할 수 있습니다:
[마크다운 출력]
```

### Notion 페이지 구조

```
개발 프로세스
├── {날짜} — {기능명}
│   ├── 1. 서비스 기획 — 플로우 검토 결과
│   ├── 2. 피쳐 기획 — 케이스 목록 + 요구사항 검토
│   ├── 3. 설계 — 스키마 + API 명세
│   ├── 4. 개발 — 태스크 이력 + 발견 사항
│   └── 5. 검증 — 코드 리뷰 + 버그 분석
```

### 저장 내용 선별 기준

모든 대화를 저장하지 않는다. 다음만 저장한다:
- 최종 결정 사항
- 발견한 문제와 해결 방법
- 반복 적용할 패턴이나 원칙
- 범위 밖 발견 사항 (나중에 처리할 것들)

### Notion 마크다운 형식 출력

```markdown
# {기능명} — {날짜}

## 단계: {1~5단계 중 해당}

### 주요 결정 사항
- [결정 1]
- [결정 2]

### 발견한 문제
| 문제 | 등급 | 처리 상태 |
|------|------|---------|
| [문제] | 블로킹/주요/선택 | 완료/대기 |

### 범위 밖 발견 사항 (별도 처리 필요)
- [항목]

### 다음 단계
- [할 것]
```

## CLAUDE.md 저장

CLAUDE.md에는 상세 내용이 아닌 **포인터와 컨텍스트**만 기록한다.

### 기록 대상

- 이번 작업에서 확정된 기술 스택/패턴
- 반복하지 말아야 할 실수
- 다음 세션에서 계속할 지점

### 기록 위치

CLAUDE.md의 기존 구조를 유지하면서 추가한다. 새 섹션을 만들지 않고 적절한 기존 섹션에 편입한다.

### 저장 후 확인

저장 완료 후 사용자에게 보고:
```
## 저장 완료

### Notion
- 페이지: [페이지 제목]
- 저장된 항목: [개수]개

### CLAUDE.md
- 추가된 내용: [요약]
```
