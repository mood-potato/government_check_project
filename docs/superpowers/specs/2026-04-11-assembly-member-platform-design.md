## 1. 서비스 목적 & 핵심 가치

**해결하는 문제:**
> 투표할 때 국회의원이 어떤 사람인지 알기 어렵다

**핵심 가치:**
- 특정 의원이 어떤 이슈에 관심 있는지 발언 기반으로 보여준다
- 특정 이슈에 관심 있는 의원을 찾을 수 있다
- 원시 데이터가 아닌 "이 사람이 실제로 무슨 말을 했는가"를 보여준다

**데이터 출처:**
- 국회 회의록 PDF (기존 수집 중)
- 의안별 회의록 API (`OOWY4R001216HX11526`, 신규)
- 18-22대 국회의원 기본정보 CSV (`data/18대-22대 국회의원 기본정보 - 정보.csv`)

## 2. 사용자 시나리오

**시나리오 A — 의원 검색**
> "홍길동 의원이 어떤 사람인지 알고 싶다"

1. 의원 이름 검색 또는 의원 목록에서 선택
2. 프로필 페이지: 주요 활동 위원회, 이슈 태그, 실제 발언 목록

**시나리오 B — 통합 검색**
> "기후변화" 또는 "탄소중립기본법" 검색

1. 검색창에 이슈 키워드 또는 의안명 입력
2. 결과 페이지:
   - 의원 탭: 관련 발언이 많은 의원 순 + 대표 발언 1개
   - 발언 탭: 관련 발언 목록 (의원명, 날짜, 회의명, 발언 발췌)
3. 의원 클릭 → 해당 이슈 관련 발언 필터된 프로필 페이지

## 3. 기능 목록

### 기존 유지

| 기능 | 설명 |
|------|------|
| 회의록 PDF 수집 | 국회 일정 API → PDF → 발언 추출 → speeches 저장 |
| 벡터화 | 발언 → Qdrant 임베딩 (증분 처리) |

## 4. 케이스 목록

### 기능 1. 의안별 회의록 수집 파이프라인

**Happy Path**
- [ ] 의안 API 호출 → 의안 목록(의안번호, 의안명, 제안일, 처리결과) 수집
- [ ] `bills` 테이블에 저장
- [ ] 의안-회의 매핑 → `bill_meetings` 테이블로 기존 `pdf_url`과 연결
- [ ] 이미 수집된 의안은 건너뜀 (증분 처리)

**Edge Case**
- [ ] 같은 의안이 여러 위원회에서 논의된 경우 → 다대다 매핑 허용
- [ ] 처리결과가 없는 의안 (심의 중) → null 허용, 추후 업데이트
- [ ] `pdf_url` 테이블에 없는 회의와 매핑되는 경우 → 매핑 skip, 로그 기록

**Error Case**
- [ ] 의안 API 타임아웃/5xx → 재시도 1회 후 해당 배치 skip, 로그 기록
- [ ] `bills` 저장 성공 후 `bill_meetings` 매핑 실패 → 롤백, 재시도 대상 표시

---

### 기능 2. 이슈 카테고리 매핑

**Happy Path**
- [ ] `issue_mapping.yaml` 로드
- [ ] `speeches.title` → 이슈 태그 배열로 변환 (`speeches.issue_tags` 컬럼 저장)
- [ ] 매핑 파일 업데이트 시 기존 speeches 재계산 배치 실행

**Edge Case**
- [ ] 매핑 안된 회의 제목 → 빈 배열 `[]` 저장, 별도 로그에 누락 제목 기록
- [ ] `speeches.title` null → 이슈 태그 없음으로 처리
- [ ] 복수 이슈 매핑 (환경노동위원회 → `["환경", "노동"]`) → 배열로 저장

**Error Case**
- [ ] `issue_mapping.yaml` 파일 없음 → 파이프라인 중단, 명확한 에러 메시지 출력
- [ ] yaml 형식 오류 → 파이프라인 중단, 오류 위치 명시

---

### 기능 3. 의원 프로필 생성 (배치)

**Happy Path**
- [ ] 의원 CSV 로드 → 의원 이름 목록으로 speakers 테이블 필터 (비의원 제외)
- [ ] 의원별 전체 발언 집계
- [ ] 이슈 태그별 발언 수 계산 → 상위 5개 이슈 추출
- [ ] 위원회별 발언 수, 총 발언 수, 활동 기간 계산
- [ ] `speaker_profiles` 테이블에 upsert
- [ ] 트리거: 새 발언 수집 완료 후 자동 실행

**Edge Case**
- [ ] 발언 0건인 의원 → 프로필 생성 skip
- [ ] 이슈 태그 없는 발언만 있는 의원 → 이슈 태그 `[]`, 위원회/발언 수는 정상 계산
- [ ] 동명이인 → CSV의 의원번호 또는 소속 정당으로 구분
- [ ] 재계산 중 새 발언 입력 → 재계산 완료 후 다음 배치에서 반영

**Error Case**
- [ ] DB 연결 실패 중 배치 실행 → 실패 기록 후 다음 스케줄에 재시도

---

### 기능 4. 의원 목록 페이지

**Happy Path**
- [ ] 전체 의원 목록 표시 (이름, 소속 위원회, 상위 이슈 태그 2개)
- [ ] 이슈 태그로 필터링
- [ ] 의원 클릭 → 프로필 페이지 진입

**Edge Case**
- [ ] 프로필 미생성 의원 → 목록에는 표시, 프로필 페이지에서 실시간 집계
- [ ] 이슈 필터 결과 없음 → "해당 이슈의 발언이 없습니다" 표시

**Error Case**
- [ ] 의원 목록 로드 실패 → 에러 메시지 표시

---

### 기능 5. 의원 프로필 페이지

**Happy Path**
- [ ] 기본 정보: 이름, 소속 위원회, 활동 기간
- [ ] 이슈 태그 상위 5개 (발언 비율 기반)
- [ ] 위원회별 발언 수 차트
- [ ] 최근 발언 목록 20건씩 페이지네이션
- [ ] 관련 의안 목록

**Edge Case**
- [ ] 이슈 태그 없는 의원 → "분류된 발언 없음" 표시
- [ ] `speaker_profiles` 미생성 → 실시간 집계 후 표시

**Error Case**
- [ ] 존재하지 않는 의원 접근 → 404 페이지

---

### 기능 6. 통합 검색

**Happy Path**
- [ ] 검색어 입력 (이슈 키워드 또는 의안명)
- [ ] 1단계: 회의 제목으로 관련 위원회 필터 (DB)
- [ ] 2단계: Qdrant 의미 검색 → 관련 발언 추출
- [ ] 3단계: 의원별 집계
- [ ] 결과: 의원 탭 (관련 발언 수 순) + 발언 탭 (최신순)
- [ ] 페이지네이션: 탭별 20건씩
- [ ] 탭 전환 시 재검색 (추후 캐싱으로 개선 가능하도록 서비스 레이어 분리)

**Edge Case**
- [ ] 검색 결과 없음 → "관련 발언을 찾을 수 없습니다" 빈 상태
- [ ] 결과 과다 → 상위 50건만 표시, "더 구체적인 키워드를 입력하세요" 안내
- [ ] 2글자 미만 검색어 → "2글자 이상 입력해주세요" 즉시 안내
- [ ] 의안번호 직접 입력 (`2200001` 형식) → 의안 검색으로 처리

**Error Case**
- [ ] Qdrant 서버 다운 → "검색 서비스 일시 중단" 안내, DB 키워드 검색으로 fallback
- [ ] 검색 3초 초과 → 타임아웃 에러 표시

---

### 기능 7. 발언 상세

**Happy Path**
- [ ] 발언 전문 표시
- [ ] 회의 컨텍스트: 날짜, 위원회, 관련 의안
- [ ] 앞뒤 발언 링크 (같은 회의 내)
- [ ] 해당 의원의 관련 발언 (같은 이슈 태그) 3건 표시

**Edge Case**
- [ ] 첫 번째/마지막 발언 → 앞/뒤 발언 링크 없음 처리
- [ ] 매우 긴 발언 (3000자+) → 전체 표시, 스크롤

**Error Case**
- [ ] 존재하지 않는 발언 ID 접근 → 404 페이지

- 의원 간 비교 기능

## 6. 데이터 흐름

```
[수집]
국회 API (일정) ──────────────────────────→ pdf_url 테이블
의안별 회의록 API ──→ bills + bill_meetings ─→ pdf_url과 매핑
의원 CSV ────────────────────────────────→ speaker_profiles 필터 기준

[처리]
pdf_url → PDF 다운로드 → 발언 추출 → speeches 테이블
speeches.title → issue_mapping.yaml → speeches.issue_tags
speeches → Qdrant 벡터화
speeches 집계 → speaker_profiles 테이블 (배치)

[검색]
검색어 → DB 위원회 필터 → Qdrant 의미 검색 → 의원별 집계 → 결과
```
