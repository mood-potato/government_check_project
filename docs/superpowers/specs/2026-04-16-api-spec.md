# API Specification

**작성일:** 2026-04-16
**상태:** Draft
**버전:** v1

---

## 1. 개요

이 문서는 홈 화면과 인물 상세 페이지를 위한 v1 API 계약을 정의한다.

이번 단계에서 우선 구현할 엔드포인트는 아래 두 개다.

- `GET /api/home`
- `GET /api/members/{member_slug}`

핵심 원칙:

- API는 `화면 단위 DTO`를 반환한다.
- 프런트엔드가 DB 테이블 구조를 직접 조립하지 않는다.
- 외부 URL 식별자는 `slug`, 내부 관계 식별자는 `id`를 유지한다.

---

## 2. 공통 규칙

### 2.1 Base URL

```text
/api
```

### 2.2 Content Type

모든 응답은 JSON을 사용한다.

```http
Content-Type: application/json
```

### 2.3 날짜 포맷

모든 날짜 문자열은 아래 형식을 사용한다.

```text
YYYY-MM-DD
```

예:

- `2026-04-16`
- `2024-02-03`

### 2.4 식별자 규칙

| 필드 | 용도 |
|---|---|
| `id` | 내부 식별자 |
| `slug` | URL 식별자 |
| `member_slug` | 인물 상세 path parameter |

### 2.5 빈 상태 규칙

- 섹션 데이터가 없을 때는 에러 대신 빈 배열 `[]` 사용
- 홈 히어로가 없을 때는 `hero: null`
- 존재하지 않는 `member_slug`는 `404 Not Found`

### 2.6 에러 응답 포맷

기본적으로 FastAPI 표준 에러 포맷을 따른다.

예:

```json
{
  "detail": "Member not found"
}
```

## 3. Endpoint Summary

| Method | Path | 목적 | 성공 응답 |
|---|---|---|---|
| `GET` | `/api/home` | 홈 화면 전체 데이터 | `200 OK` |
| `GET` | `/api/members/{member_slug}` | 인물 상세 전체 데이터 | `200 OK` |

- `GET /api/home`의 세부 분리
  - `/api/home/hero`
  - `/api/home/recent`
  - `/api/home/featured`
- `GET /api/members/{member_slug}`의 세부 분리
  - `/summary`
  - `/conflicts`
  - `/bills`
- 정렬/필터 query parameter
- pagination

현재 단계에서는 `페이지 단위 응답`이 우선이다.
